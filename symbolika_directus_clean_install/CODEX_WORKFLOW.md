# Рабочая инструкция для Codex

Этот файл - короткая точка входа в проект. Его нужно читать перед новой задачей, чтобы не держать в контексте длинную историю чата и тяжелые спецификации.

## Как начинать задачу

1. Прочитать этот файл.
2. Прочитать `CURRENT_HANDOFF.md`: там зафиксированы текущий релиз, последнее изменение и важные ограничения деплоя.
3. Если нужна бизнес-логика шире текущей задачи, открыть `PROJECT_CONTEXT.md`.
4. Проверить `git status --short`.
5. Открывать только файлы, которые относятся к текущей задаче.
6. Не трогать чужие изменения и не откатывать файлы без явного запроса.

## Какие файлы читать

- Рабочий центр и основной новый интерфейс: `extensions/symbolika-costing-module/index.js`.
- SQL, таблицы, роли, права, представления, триггеры: `setup/create-work-views.sql`.
- Правки стандартной админки Directus: `setup/symbolika-admin-ui.js` и `setup/symbolika-admin-ui.css`.
- Серверные расчеты, статусы, оплаты, уведомления: `extensions/symbolika-calculations/` и `extensions/symbolika-push/`.
- Контрагентский интерфейс: `extensions/symbolika-contractor-module/`.
- Задачи и таск-трекер: `extensions/symbolika-tasks-module/`.

## Что не читать без явной необходимости

- `TZ_CONSTRUCTOR_SPEC.md` - большая спецификация конструктора ТЗ. Конструктор собран, к нему вернемся позже.
- `setup/create-tz-constructor.sql` - читать только при задачах по конструктору ТЗ.
- `backups/*.dump`, `database/`, большие логи и временные файлы.

## Карта логики

- Основная работа пользователей должна идти через собственные интерфейсы, а не через стандартные коллекции Directus.
- Стандартные коллекции Directus остаются техническим нижним уровнем, доступ по возможности только админу.
- Менеджер видит свои заказы; админ и управляющий видят свои и все заказы.
- Клиент может заказывать лично или от компании. Если в заказе выбрана компания, плательщиком считается компания.
- Оплаты распределяются по заказу и позициям последовательно. Частичная оплата закрывает позиции сверху вниз.
- Оплаты контрагентам не должны второй раз уменьшать прибыль: себестоимость уже заложена в позициях.
- Производство и шелкография видят только свои позиции и меняют только производственные статусы и комментарии.
- Офис работает с заказами к выдаче, заказами в офисе и выданными заказами; при выдаче можно принять оплату.
- Заготовки для текстиля и сувенирки идут в закупку, указываются поставщик, источник и стоимость.
- Склад и закупки нужны для производства, шелкографии, админа и управляющего.

## Статусы

Основные статусы заказов и позиций:

- Новый
- Согласование
- Доработка макета
- Отправлен в работу
- В работе
- Готов
- Доставлен / Выдан
- Отменен

Синхронизация:

- Если все позиции готовы, заказ становится готов.
- Если заказ готов, все позиции становятся готовы.
- Если все позиции доставлены или выданы, заказ становится доставлен / выдан.
- Если заказ доставлен / выдан, все позиции становятся доставлены / выданы.
- Если производство ставит "Готов", позиция становится "Готов".
- Если производство ставит "Доработка макета", позиция становится "Доработка макета".

## UI-правила

- Основная тема эксплуатации - темная.
- Визуальный стиль: лаконичный, плотный, iOS/macOS inspired, без ощущения наложенных друг на друга правок.
- Левое меню должно быть компактным, не обрезать текст и уметь сворачиваться.
- На страницах не должно быть лишнего горизонтального скролла.
- Таблицы должны помещать ключевую информацию в один экран.
- Строка таблицы открывает карточку по клику на свободное место.
- Кнопка "Инфо" не нужна, если строка открывается кликом.
- Статусы показывать русским текстом и цветными пинами/селектами.
- Выпадающие списки в темной теме не должны открываться белыми.
- Не показывать кнопку "Новый заказ" там, где она не относится к задаче страницы.
- Не показывать фильтр "Все", если других вариантов фильтра на странице нет.
- Быстрые карточки закрываются крестиком и кликом по свободной области слева от карточки.

## Проверка

После правок JS:

```powershell
node --check symbolika_directus_clean_install\extensions\symbolika-costing-module\index.js
node --check symbolika_directus_clean_install\setup\symbolika-admin-ui.js
```

После SQL-правок:

```powershell
cmd /c "docker exec -i symbolika-db psql -v ON_ERROR_STOP=1 -U directus -d directus < symbolika_directus_clean_install\setup\create-work-views.sql"
docker restart symbolika-directus
docker logs --tail 80 symbolika-directus
```

Интерфейс и права проверять через Playwright под нужными ролями: админ, управляющий, менеджер, производство, шелкография, офис, дизайнер.

## Git и дампы

- Перед коммитом всегда смотреть `git status --short`.
- Не коммитить живые дампы, `database/`, секреты и временные файлы.
- PostgreSQL dump для переноса делать только custom-форматом `pg_dump -Fc` и проверять через `pg_restore --list`.
- Shell-скрипты `*.sh` должны быть в LF.
- На рабочем VPS не применять полный `setup/create-work-views.sql` автоматически. Сначала сделать custom dump и архив uploads, затем использовать только относящиеся к релизу точечные миграции из `setup/migrations/`. Актуальные детали и последние бэкапы перечислены в `CURRENT_HANDOFF.md`.
