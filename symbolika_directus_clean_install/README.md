# Symbolika Directus

Локальная учетная система «Символика» на Directus 11 + PostgreSQL.

Админка:

```text
http://localhost:8057/admin/
```

Основные контейнеры:

```text
symbolika-directus
symbolika-db
```

## Назначение системы

Система ведет заказы, позиции заказов, клиентов, компании, оплаты, офисную выдачу, производство, шелкографию, себестоимость, расходы и управленческие показатели.

Основной рабочий интерфейс постепенно перенесен из стандартных коллекций Directus в кастомные модули. Стандартные коллекции остаются техническим нижним уровнем и должны быть доступны в первую очередь админу.

## Основные роли

- Админ — полный доступ, справочники, права, финансы, расходы, зарплаты.
- Управляющий — управление заказами, себестоимость, производство, основные финансы без лишних технических действий.
- Менеджер — свои заказы, свои клиенты, оплаты, сверки, офисные выдачи.
- Офис-менеджер — выдача заказов в офисе, прием оплат, офисные статусы.
- Производство — только свои позиции производства.
- Шелкография — только свои позиции шелкографии.
- Контрагент — будущий внешний кабинет для подрядчиков.

## Ключевые расширения

- `extensions/symbolika-costing-module` — основной рабочий интерфейс.
- `extensions/symbolika-admin-module` — раздел админки.
- `extensions/symbolika-clients-module` — клиенты и компании.
- `extensions/symbolika-finance-module` — финансы и сверки.
- `extensions/symbolika-management-module` — управление и себестоимость.
- `extensions/symbolika-production-module` — производство, шелкография, этикетки.
- `extensions/symbolika-contractor-module` — будущий кабинет контрагента.
- `extensions/symbolika-calculations` — серверные расчеты, статусы, оплаты, синхронизация.
- `extensions/symbolika-push` — браузерные push-уведомления и VK.
- `extensions/symbolika-notifications-module` — персональный центр уведомлений сотрудников с выбором типов событий и каналов доставки push, e-mail, VK и Telegram.
- `extensions/symbolika-yandex-disk` — защищенная серверная загрузка макетов позиций на Яндекс Диск; токен остается на сервере, а в позиции сохраняются публичная ссылка и метаданные файла.
- `extensions/symbolika-order-link`, `extensions/symbolika-office-issue-link` — старые интерфейсные ссылки между Directus-витринами.

Исторические расширения `symbolika-autosave-select` и `symbolika-live-calc-interface` не включать обратно без отдельного тестирования.

## Запуск

```bash
docker compose up -d
```

Первичный импорт:

```bash
docker exec -it symbolika-directus node /directus/setup/import-symbolika.mjs
```

Применить SQL-настройки:

```bash
docker exec -i symbolika-db psql -v ON_ERROR_STOP=1 -U directus -d directus < setup/create-work-views.sql
docker restart symbolika-directus
```

На Windows из корня репозитория:

```powershell
cmd /c "docker exec -i symbolika-db psql -v ON_ERROR_STOP=1 -U directus -d directus < symbolika_directus_clean_install\setup\create-work-views.sql"
docker restart symbolika-directus
```

## Бэкап и восстановление

Для переноса базы использовать только PostgreSQL custom dump (`-Fc`).

Создать дамп:

```bash
docker exec symbolika-db pg_dump -U directus -d directus -Fc -f /tmp/directus.dump
docker cp symbolika-db:/tmp/directus.dump ../backups/directus.dump
```

Проверить дамп:

```bash
pg_restore --list ../backups/directus.dump
```

Восстановить:

```bash
docker cp ../backups/directus.dump symbolika-db:/tmp/directus.dump
docker exec symbolika-db pg_restore -U directus -d directus --clean --if-exists /tmp/directus.dump
docker restart symbolika-directus
```

Обычный SQL dump не использовать для деплоя на VPS.

## Правила статусов

Актуальные статусы заказов и позиций:

- Новый
- Согласование
- Доработка макета
- Отправлен в работу
- В работе
- Готов
- Доставлен
- Отменен

Основная логика:

- Если производство ставит «Доработка макета», статус позиции тоже становится «Доработка макета».
- Если производство ставит «Готов», позиция становится «Готов».
- Если все позиции готовы, заказ становится «Готов».
- Если заказ становится «Готов», все позиции становятся готовыми.
- Если все позиции доставлены/выданы, заказ становится доставленным/выданным.
- Если заказ доставлен/выдан, все позиции становятся доставленными/выданными.
- Аналогично для отмены.
- Если все позиции в офисе, заказ получает офисный статус «В офисе».
- Если хотя бы одна позиция не в офисе, заказ получает «Не в офисе».

## Оплаты и сверки

- Платежи и управленческие финансы — разные блоки.
- Менеджер работает с оплатами по заказам и сверками.
- При оплате через офисную выдачу платеж должен автоматически привязываться к текущему заказу и распределяться по нему.
- Если заказ оформлен на компанию, плательщиком для сверки считается компания.
- Если компания не выбрана, плательщиком считается клиент.
- Частичная оплата распределяется по позициям сверху вниз.

## Производство и шелкография

В производственные разделы должны попадать позиции, которые:

- отправлены в работу;
- имеют соответствующего подрядчика или производственный участок;
- не находятся в архивном/завершенном состоянии, если открыт активный список.

Производство и шелкография работают со статусом производства и комментарием производства. Админ и управляющий также могут менять производственный статус.

## Себестоимость и маршрутизация

Себестоимость заполняется через управленческий интерфейс. Основные поля:

- подрядчик 1;
- себестоимость 1;
- подрядчик 2;
- себестоимость 2.

Маршрутизация подрядчиков должна идти через `product_routing_rules`, а не через случайные поля у контрагентов.

Для текстиля и сувенирки используется логика заготовок:

- менеджер выбирает поставщика заготовки;
- можно указать «заготовка заказчика»;
- стоимость заготовки учитывается как первая часть себестоимости;
- нанесение идет вторым подрядчиком по правилам маршрутизации.

## UI-принципы

- Основной интерфейс — темная тема.
- Рабочие операции делаются в кастомных модулях.
- Таблицы должны вмещать ключевую информацию без горизонтального скролла, где это возможно.
- Статусы показываются русским текстом и цветом.
- Быстрые карточки показывают полезную информацию без внутренних id.
- Меню должно быть компактным и не обрезать пункты.
- Ссылки на стандартную админку Directus использовать только там, где нет альтернативы в рабочем интерфейсе.
